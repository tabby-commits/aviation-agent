# RAG Retrieval Evaluation

This directory (`rag_eval/`) holds the offline retrieval-evaluation workflow for the aerospace-news knowledge base, separate from the Java package `com.kama.jchatmind.evaluation`.

## Workflow

1. Prepare or review `datasets/question_bank.en.jsonl`.
2. Start the Spring Boot backend.
3. Call the evaluation export endpoint to retrieve candidate chunks for each question.
4. Run `scripts/build_eval_dataset.py` to draft `datasets/eval_set.en.jsonl`.
5. Review the generated references and supporting chunk ids.
6. Call the export endpoint again with `eval_set.en.jsonl` to produce a labeled retrieval export.
7. Run `scripts/run_ragas_retrieval_eval.py` to score retrieval quality with RAGAS and deterministic IR metrics.
8. Run `scripts/summarize_eval.py` to generate a markdown summary.

## Directory layout

- `datasets/`: question bank and labeled evaluation set.
- `artifacts/`: retrieval exports generated by the backend.
- `reports/`: CSV and markdown evaluation reports.
- `scripts/`: Python helpers for dataset drafting and scoring.

## Retrieval export API

Send a request to `POST /api/evaluations/retrieval/export`.

Example request body:

```json
{
  "kbId": "00000000-0000-0000-0000-000000000002",
  "datasetFilename": "question_bank.en.jsonl",
  "outputFilename": "retrieval_export_bootstrap.jsonl",
  "topN": 5
}
```

PowerShell example:

```powershell
$body = @{
  kbId = "00000000-0000-0000-0000-000000000002"
  datasetFilename = "question_bank.en.jsonl"
  outputFilename = "retrieval_export_bootstrap.jsonl"
  topN = 5
} | ConvertTo-Json

Invoke-RestMethod `
  -Method Post `
  -Uri "http://localhost:8080/api/evaluations/retrieval/export" `
  -ContentType "application/json" `
  -Body $body
```

## Python setup

```powershell
python -m venv .venv
.\.venv\Scripts\activate
pip install -r .\rag_eval\requirements.txt
```

Create `rag_eval/.env` from `rag_eval/.env.example` before running scripts that call an OpenAI-compatible model.

## Notes

- The bootstrap export generated from `question_bank.en.jsonl` is intentionally unlabeled.
- `build_eval_dataset.py` uses the bootstrap export plus an OpenAI-compatible model to draft reference answers and supporting chunk ids.
- Deterministic metrics such as `Recall@k` require `reference_context_ids`, so review `eval_set.en.jsonl` before trusting the final report.
- If the export endpoint reports that the knowledge base has no retrievable chunks, check whether `chunk_bge_m3` was populated successfully. In this project, document import can succeed even when the embedding service at `localhost:11434` is unavailable, which leaves `document` rows without retrievable chunks.
