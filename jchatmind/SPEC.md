## 1. 目的

本阶段在既有论文数据层、新闻知识库、四个论文工具和运行评价接口之上，完成低轨卫星星座网络方向的正式阶段性实证。工作顺序固定为：

1. 按中期报告现行定义重做三个 Skill；
2. 清理并冻结论文、参数和新闻实验数据；
3. 对竞争力分析框架中现有论文与新闻能够支撑的指标开始计算或定量分析；
4. 运行论文计量、技术与工程量化、新闻事件三类真实任务；
5. 保存报告、证据、计算过程和人工核验结果。

本 SPEC 替代上一版“数据接入与工具开发”规格。上一版已经完成的论文导入、参数导入、分类查询、文献计量工具和评价接口不重复开发；除非本 SPEC 的数据一致性门或实验运行暴露缺陷，否则只做必要修正。

## 2. 权威口径与研究边界

### 2.1 指标框架权威来源

本 SPEC 以当前中期报告 `完整稿件.md` 第 3.2 节为唯一指标定义来源，采用四个一级维度、28 项通用指标：

- 战略重要性（1）—（5）；
- 技术前瞻性（6）—（8）；
- 科技创新能力（9）—（18）；
- 产业成熟度（19）—（28）。

项目说明文件中仍存在“30 项”旧表述时，不得同时保留两套口径。实施前必须将项目说明、三个 Skill、测试和实验输出统一到中期报告现行的 28 项定义。若用户或导师后续正式修改中期报告，则先更新本 SPEC，再修改 Skill 和实验。

### 2.2 本阶段数据范围

仅使用两类数据：

1. **论文**：WoS 元数据、人工筛选结论、论文核心页 RAG、论文技术归属和人工审核参数证据；
2. **新闻**：本地新闻知识库中的 SpaceNews 报道及由其形成的人工核验事件表。

新闻知识库当前为单一媒体来源。本阶段所有新闻统计必须表述为“SpaceNews 报道样本中的公开记录”，不得外推为中美全部新闻、全部工程活动或全部产业事实。

### 2.3 本阶段不做

- 不做论文趋势与新闻事件之间的时间对应、领先滞后或相关性分析；
- 不使用新闻事件解释论文数量变化的原因；
- 不做可复用火箭案例；
- 不接入政策、专利、标准、市场规模、财务和供应链新数据；
- 不与 ChatGPT、DeepSeek 或其他平台横向比较；
- 不计算综合竞争力得分或总体排名；
- 不放宽当前严格可比中美技术参数对为 0 组的结论；
- 不把未检索到公开信息解释为相关主体不具备相应能力。

## 3. 核心设计决定

### 3.1 三类任务、四个具体实验

本阶段保留三类任务，其中“技术与工程量化”拆成两个证据性质不同的实验：

| 任务类别 | 具体实验 | 主要数据 | 主要指标 |
|---|---|---|---|
| A. 论文计量 | A1 中美论文规模、影响、趋势、合作和机构结构 | 论文元数据 | （9）（10）（11）（12）（16） |
| B. 技术与工程量化 | B1 论文技术参数热点与变化 | 参数证据、论文元数据 | （13）（14） |
| B. 技术与工程量化 | B2 发射、部署和在轨规模 | 新闻事件证据 | 主要为（23），条件满足时辅助（22）（25） |
| C. 新闻事件 | C1 头部主体布局与应用拓展 | 新闻事件证据 | （5）（26），必要时提供（8）（19）的线索 |

每个具体实验使用两种语义等价、措辞不同的问题运行一次，共形成 8 份报告。两次运行使用同一数据快照、同一时间范围、同一模型配置和同一 Skill 版本，用于检查检索证据与核心结论的稳定性。

### 3.2 “发射次数、在轨卫星数量”的归属

发射次数、部署批次、已部署卫星数量和在轨卫星数量不属于论文性能参数，不进入指标（13）（14）的参数比较表。它们属于工程供给和任务执行事实，主要映射到指标（23）“产能水平”。

- **年度发射次数**：流量指标，按自然年统计完成的、与目标星座直接相关的发射任务数；
- **部署批次**：流量指标，按任务或批次去重；同一任务的多篇报道只计一次；
- **部署卫星数量**：流量指标，记录单次或年度实际部署量；
- **在轨卫星数量**：存量快照，必须保存统计日期和状态定义，不得把不同日期的快照相加；
- **运营卫星数量**：与“已发射”“已部署”“仍在轨”分开记录；没有状态证据时不得互换；
- **发射主体归属**、**星座运营主体归属**和**发射场所在国**分列，不以任一字段替代国家归属。

当新闻提供产品型号、链路性能、容量或寿命等产品级参数时，可作为指标（22）“同类工程产品性能”的候选证据，但只有对象、单位、时间点和任务条件一致时才能并列比较。版本时间和经验证改进记录完整、同一产品谱系至少形成三个主要版本时，才允许计算指标（25）的典型迭代周期。

## 4. 28 项指标在“论文 + 新闻”范围内的可分析性

状态定义：

- **可计算**：现有结构化数据和公式足以直接计算；
- **可定量描述**：可形成事件数、记录数、分布或事实表，但不构成综合评分；
- **条件可分析**：需满足同对象、同口径、证据完整或人工核验条件；
- **本阶段不分析**：当前论文与新闻数据不足以支持。

| 指标 | 状态 | 本阶段方法与边界 |
|---|---|---|
| （1）战略政策强度 | 本阶段不分析 | 缺少正式政策文件库；新闻提及不能替代政策原文 |
| （2）国家安全关联程度 | 本阶段不分析 | 缺少功能等价的公开战略文件集合 |
| （3）关键技术管制程度 | 本阶段不分析 | 缺少法规、清单及版本化管制数据 |
| （4）国家重大项目部署 | 本阶段不分析 | 新闻只能提供线索，不能替代项目和预算文件 |
| （5）头部航天主体布局动向 | 可定量描述 | 固定主体名单后，统计主体—行动—对象—时间事件及行动类型分布；结果限定为 SpaceNews 样本 |
| （6）关键技术清单优先级 | 本阶段不分析 | 缺少官方关键技术清单 |
| （7）前沿技术清单优先级 | 本阶段不分析 | 缺少正式前沿清单和预见材料 |
| （8）范式变革潜力 | 条件可分析 | 论文摘要和新闻可提供架构、任务流程或应用边界变化线索；只作证据化定性研判 |
| （9）核心论文数量 | 可计算 | 完全计数和分数计数；按国别、年份和技术范围报告 |
| （10）高被引论文数量与占比 | 可计算 | 同专题、同年份、同文献类型参照组；阈值并列按分数分配 |
| （11）研究热度趋势 | 可计算 | 年度序列、绝对增量、三年后向移动平均和满足条件时的 CAGR |
| （12）国际合作论文比例与结构 | 可计算 | 完全计数识别合作关系，分数计数计算国家或机构贡献 |
| （13）已公开最高技术指标 | 可定量描述 | 输出参数族、技术对象、数值、单位、条件、页码和分布；当前不得形成中美性能排名 |
| （14）公开技术性能变化 | 条件可分析 | 仅同一技术对象、同参数、同工况记录按时间排序；不满足条件时只并列证据 |
| （15）研发资金投入强度 | 本阶段不分析 | 缺少预算、合同、财务和价格口径数据 |
| （16）科研机构贡献 | 可计算 | 机构分数贡献、份额、HHI 和有效机构数；报告地址解析覆盖率 |
| （17）核心技术自主控制能力 | 本阶段不分析 | 论文和新闻不能单独证明自主控制能力 |
| （18）技术标准主导权 | 本阶段不分析 | 缺少标准组织正式角色和提案数据 |
| （19）技术成熟度 | 条件可分析 | 新闻任务与运行证据可作为 TRL 候选证据；不得仅凭报道用语自动判级 |
| （20）专利族申请与授权规模 | 本阶段不分析 | 无专利数据 |
| （21）国际专利申请 | 本阶段不分析 | 无 PCT 和三方专利族数据 |
| （22）同类工程产品性能 | 条件可分析 | 新闻中的产品级参数需统一对象、条件、单位和统计时点；发射次数和在轨数量不属于本指标 |
| （23）产能水平 | 可定量描述 | 统计发射任务、部署批次、部署数量、在轨存量快照和地面设施建设记录 |
| （24）核心供应链保障能力 | 本阶段不分析 | 缺少供应商、产能、替代验证和来源份额数据 |
| （25）产品迭代速度 | 条件可分析 | 版本事件完整且至少有两个相邻间隔时计算中位迭代周期；新闻提及不等于经验证改进 |
| （26）应用拓展能力 | 可定量描述 | 统计应用领域、迁移案例、用户类型、重复任务和持续服务线索；限定为 SpaceNews 样本 |
| （27）相关产业市场规模 | 本阶段不分析 | 缺少同边界收入、增加值或产值序列 |
| （28）产业市场规模增长速度 | 本阶段不分析 | 缺少同来源、同边界、不变价产业规模序列 |

本阶段允许优先产出：（9）（10）（11）（12）（16）的公式结果；（5）（13）（23）（26）的描述性定量结果；（8）（14）（19）（22）（25）仅在各自准入条件满足时产出。

## 5. 三个 Skill 重构要求

三个 Skill 必须先于正式计算和实验运行完成。三者互相引用但不复制大段内容，各自只承载一种职责。

### 5.1 `competitiveness-framework`

**职责**：保存中期报告四维 28 项指标的定义、分析单元、所需字段、处理方式、适用条件和解释边界，并负责从问题中选择最小足够指标组合。

必须包含：

1. 28 项指标名称和编号与中期报告逐项一致；
2. 每项指标标明方法类型：公式计算、描述性定量、事实表或结构化研判；
3. 每项指标标明最低证据要求和禁止结论；
4. “只使用论文与新闻”场景的可分析性矩阵，与本 SPEC 第 4 节一致；
5. 指标选择规则：先界定对象、国家归属、时间窗和证据范围，再选择指标；
6. 报告必须列出已选指标、未选指标及原因；
7. 不计算综合得分和总体排名；
8. 不把发射次数、部署数量和在轨卫星数量归入论文技术参数；
9. 输出结构：问题界定—指标选择—数据与口径—分指标结果—综合判断—缺口与边界。

### 5.2 `data-resource-rules`

**职责**：规定论文元数据、论文核心页 RAG、参数证据、技术归属和新闻知识库的证据角色、调用顺序、数据版本、引用方式与冲突处理。

必须包含：

1. 数值与统计优先使用结构化论文和参数数据，不从 RAG 片段估算全量论文数；
2. 新闻知识库仅代表 SpaceNews 报道样本，不代表新闻总体；
3. 新闻转述的发射、卫星数量和产品参数必须保存 URL、报道日期、事件日期、证据原文和转述状态；
4. 本阶段不调用外部 Web 增补数据；若新闻无法回查原始来源，标记“新闻转述，原始来源未核验”；
5. 论文引用保留 `docId`、标题、年份和必要页码；参数引用必须保留证据原文和页码；
6. 所有实验绑定数据快照 ID、文件哈希、数据库统计、Skill 版本和执行时间；
7. 测试文档不得进入正式论文或新闻知识库；测试必须使用独立 KB 或独立数据库；
8. 数据冲突不静默覆盖：保留不同来源数值、统计时点和口径，说明最终采用规则；
9. 新闻事件去重以同一任务、同一主体、同一事件日期和同一对象为核心，不以报道篇数代替事件数。

### 5.3 `ci-analysis-methods`

**职责**：规定文献计量、论文参数分析、工程规模统计、新闻内容分析和定性研判的准入条件、计算流程及表达规范。

必须包含：

1. 指标（9）（10）（11）（12）（16）的公式、输入检查和适用域；
2. 参数证据按“论文数”和“参数记录数”两种单位分开统计；
3. 同一论文多次报告同一参数族时，论文覆盖率只计一次；
4. 参数比较逐项核对技术对象、任务、数据集、硬件与网络环境、基线、单位和结果形式；
5. 当前严格可比中美参数对为 0 组时，只报告参数热点、报告率、证据分布和国别内部可比变化；
6. 工程规模区分流量和存量，区分星座运营主体、发射服务商与发射地；
7. 发射任务、部署批次和新闻报道分别去重，不把报道篇数当作发射次数；
8. 在轨数量必须带统计日期、状态口径和来源，不跨时点求和；
9. 新闻内容分析使用预先固定的“主体—行动—对象—时间—状态—来源”编码；
10. 不执行论文与新闻之间的时间相关、因果或领先滞后分析；
11. 所有结论区分事实、计算、推断和缺口；推断不得写成事实。

### 5.4 Skill 验收场景

三个 Skill 至少通过以下场景测试：

1. 用户要求“比较中美论文热度”时，选择（9）—（12）中的最小组合并调用文献计量工具；
2. 用户要求“比较中美时延谁更先进”时，先执行参数可比性检查，在 0 组严格可比对条件下拒绝国别性能排名；
3. 用户要求“比较发射次数和在轨卫星数量”时，映射到（23）而不是（13）（14）；
4. 用户要求“分析主体布局”时，选择（5）并声明 SpaceNews 样本边界；
5. 用户要求“完整评价全部 28 项”但只提供论文与新闻时，明确列出本阶段不支持的指标，不编造结果；
6. 用户要求把论文增长归因于新闻事件时，拒绝因果推断并说明本阶段已排除该任务；
7. Skill 扫描、frontmatter、交叉引用、指标编号和工具名全部通过自动测试。

6. 冻结后任何数据修改必须生成新的 `snapshot_id`，不得覆盖既有实验结果。

## 7. 结构化新闻工程事件数据合同

RAG Top-K 命中不能证明全量事件数量。发射次数、部署批次和在轨卫星数量的定量分析必须先对新闻语料进行批量候选识别，再经人工核验形成结构化事件表；不得直接让大模型根据若干检索片段心算总数。

建议产物：`experiments/leo_paper_news_2020_2025/data/news_engineering_events.csv`。

必填字段：

| 字段 | 含义 |
|---|---|
| `event_id` | 稳定事件 ID |
| `country_attribution` | 按星座运营主体确定的国家归属 |
| `operator` | 星座运营主体 |
| `launch_provider` | 发射服务商 |
| `launch_country` | 发射服务商归属或发射国，和运营主体分列 |
| `event_type` | launch / deployment / in_orbit_snapshot / manufacturing / ground_infrastructure / version |
| `event_date` | 事件发生日期；未知时为空 |
| `report_date` | 新闻发布日期 |
| `constellation` | 星座或项目名称 |
| `mission_or_version` | 任务、批次或版本名称 |
| `metric_name` | launch_count / deployed_satellites / in_orbit_satellites / operational_satellites 等 |
| `value`、`unit` | 原始数值与单位 |
| `stock_or_flow` | stock / flow |
| `status_definition` | deployed / in-orbit / operational 等状态口径 |
| `source_url`、`source_title` | SpaceNews 来源 |
| `evidence_text` | 支撑该字段的原文片段 |

只有 `review_status=confirmed` 的记录进入计算。发生冲突时保留各版本，并在 `review_note` 说明采用值和理由。

## 8. 实验定义

### 8.1 A1：论文计量

**问题 1**：2020—2025 年中美低轨卫星星座网络研究在论文规模、高被引、增长趋势、国际合作和机构集中结构上呈现什么差异？

**问题 2**：在相同数据与时间边界下，分别从数量、影响、合作和组织结构说明中美 LEO 组网论文活动特征。

必须输出：

- 年度完全计数和分数计数；
- 高被引前 10% 数量与占比，含参照组和并列处理；
- 年度序列、三年后向移动平均和满足条件时的 CAGR；
- 国际合作比例和主要合作伙伴；
- 机构贡献份额、HHI 和有效机构数；
- CNKI / WoS 覆盖偏差、地址缺失和引用窗口边界。

### 8.2 B1：论文技术参数

**问题 1**：中美 LEO 组网论文主要报告哪些性能参数，参数报告率和年度分布有何特征？

**问题 2**：在不进行不可比性能排名的前提下，说明中美论文参数证据的热点、覆盖和可比性缺口。

必须输出：

- 参数族涉及论文数、参数记录数和本国每百篇论文报告率；
- 参数族按年份和国别的分布；
- 每项关键参数的技术对象、单位、条件、结果形式、证据原文和页码；
- 严格可比组数量；若为 0，明确写出“0 组严格可比对”；
- 不得以最大值、最小值或均值直接推导国家技术优劣。

### 8.3 B2：新闻工程规模

**问题 1**：2020—2025 年中美主要 LEO 星座在发射任务、部署批次、部署数量和在轨规模方面有哪些公开记录？

**问题 2**：基于经核验的 SpaceNews 事件样本，比较中美 LEO 星座工程部署节奏和在轨存量快照。

必须输出：

- 按年去重发射任务数、部署批次数和部署卫星数量；
- 指定统计日期的在轨或运营卫星数量快照；
- 运营主体、发射服务商和发射国分列；
- 规划值与实际完成量分列；
- 成功、失败、延期、状态不明分列；
- 所有结果标注“SpaceNews 报道样本”，不得推断未报道事件不存在。

### 8.4 C1：新闻主体布局与应用拓展

**问题 1**：2020—2025 年 SpaceNews 对中美主要 LEO 星座主体的投资、产品、任务、合作和产能行动有哪些记录？

**问题 2**：在固定主体和固定新闻来源范围内，中美 LEO 星座的主体布局与应用拓展呈现哪些公开特征？

必须输出：

- 实证开始前锁定的中美主体名单及纳入理由；
- 去重后的主体—行动—对象—时间事件表；
- 行动类型、涉及主体数、年份和状态分布；
- 应用领域、用户类型、重复任务和持续服务线索；
- 新闻转述、原始来源已核验和证据冲突分别标记；
- 不将新闻报道量直接解释为实际能力、投入或市场份额。

## 9. 运行、评价与稳定性检查

每次运行必须创建独立 `run_id`，保存：

- 原始问题及问题版本；
- `snapshot_id`、模型配置、代码 commit 和三个 Skill 哈希；
- 所选指标、选择理由和未选指标原因；
- 工具调用及完整参数；
- 检索命中、结构化结果和计算中间值；
- 最终报告；
- 证据引用导出；
- 修改记录。

每份报告完成八项客观检查：维度覆盖、指标理由、引用完整性、来源层级、检索可追溯、方法可复核、结论对应证据、边界表述。每项必须填写“符合”“不符合”或“证据不足”并附位置和说明，不得保留 `pending`。

人工内容核验至少覆盖：

1. 所有数值及其分子、分母、单位和时间窗；
2. 所有关键结论对应的论文、参数或新闻证据；
3. 参数可比性；
4. 新闻事件去重和国家归属；
5. 事实、计算、推断和缺口的表达边界。

同一具体实验的两个问题版本进行稳定性比较：

- 记录共同证据、仅单次命中证据和冲突证据；
- 判断核心计算结果是否一致；
- 判断核心结论是否发生实质变化；
- 差异必须回到检索表达、工具参数或证据覆盖解释，不以多数投票掩盖问题。

不计算单一综合有效性得分。

## 11. 实施顺序

1. **Gate S0：口径统一**

   确认 28 项现行框架，删除或修正项目内 30 项旧表述。
2. **Gate S1：重做三个 Skill**

   按第 5 节重写 Skill，完成静态、路由和拒绝场景测试。
3. **Gate S2：数据清理与冻结**

   隔离测试数据，核对稿件、源文件和数据库，生成 `data_snapshot.json`。
4. **Gate S3：开始计算与定量整理**

   计算（9）（10）（11）（12）（16）；整理（13）（14）；建立新闻工程与主体事件表并人工核验。
5. **Gate S4：运行 8 份报告**

   依次运行 A1、B1、B2、C1 的两个问题版本。

   完成所有检查项，修正不符合项，保留证据不足项。
7. **Gate S6：形成实证交付**

   冻结结果、评价记录和允许写入论文的结论边界。

## 12. 验收标准

只有同时满足以下条件，才能声明“LEO 论文与新闻阶段性实证完成”：

- 三个 Skill 与中期报告 28 项定义逐项一致；
- Skill 能正确区分论文性能参数与新闻工程规模事实；
- 正式 KB 中测试文档数为 0；
- `data_snapshot.json` 完整，所有运行使用同一快照；
- （9）（10）（11）（12）（16）的公式结果可由原始数据复算；
- 参数结果明确区分论文数和记录数，不产生不可比性能排名；
- 新闻工程统计来自 `confirmed` 事件，存量与流量未混算；
- 8 份报告均有正文、工具记录、证据引用和边界说明；
- 每份报告的八项客观检查均已填写，无 `pending`；
- 所有关键数值和结论完成人工核验；
- 两种问题表达的核心计算一致，结论差异有证据化解释；
- 报告明确限定为 2020—2025 年论文与 SpaceNews 新闻样本；
- 不包含论文—新闻相关性、因果或领先滞后结论；
- 不计算综合竞争力得分，不外推为整个中美航天领域结论。

## 13. 允许形成的论文表述

验收通过后，可以表述：

- 已在统一数据快照下完成 LEO 组网论文计量、论文参数证据、新闻工程部署和主体应用事件的阶段性实证；
- 智能体能够按照三个 Skill 选择现有数据可支撑的指标，调用结构化工具和新闻知识库形成带口径、证据和边界的专题报告；
- 论文数据可支持（9）（10）（11）（12）（16）的计算以及（13）（14）的受限分析；
- SpaceNews 样本可支持（5）（23）（26）的描述性定量分析，并为（8）（19）（22）（25）提供条件性证据；
- 当前严格可比中美技术参数对为 0 组，因此不形成技术性能国别排名。

- 已完成 28 项指标的完整中美竞争力评价；

- 发射次数或在轨卫星数量等同于技术先进性；
- 论文增长由某类新闻事件或工程活动导致；
- 当前阶段性结果可以代表整个中美航天领域。
