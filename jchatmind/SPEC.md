# SPEC：低轨卫星星座"论文 + 新闻"竞争力分析智能体

> 依据《基于智能体的航天领域中美科技竞争力分析》中期报告（完整稿件.md）第 3.3、3.4 节及下一步工作计划（2026.09–2026.10"两个案例准备 + 三个 Skill 实现与验证"阶段）编写。
> 范围：低轨卫星星座网络案例。可复用火箭案例数据未采集，不在本 SPEC 范围。

---

## Problem Statement

研究者已经完成了低轨卫星星座网络案例的两类数据积累（学术论文与新闻报道），但目前智能体无法使用这些数据：

1. **Skill 未按论文要求拆分**。现有单一 skill（space-tech-intelligence-analyst）使用 34 项旧指标体系，与中期报告确定的"四维度 28 项指标"框架不一致，且未拆分为论文要求的三个功能明确的 Skill（竞争力分析框架 / 数据资源检索与使用规则 / 竞争情报分析方法），无法进入工作计划中"三个 Skill 实现与验证"阶段。
2. **论文数据未进入 RAG**。2611 篇论文 PDF 全文、5628 条 WoS 元数据未入库；RAG 中目前只有新闻语料，智能体无法检索论文证据。
3. **结构化证据无可查询接口**。小论文已产出的四类高质量结构化数据——683 篇有效论文筛选表（含国别判定证据）、182 节点 EASC 分类树（含 4488 篇论文归属）、1443 条人工审核的性能参数证据（含技术对象、数值、单位、条件、证据原文、页码）、参数族归一化结果——都以 CSV 形式留在外部目录，智能体没有工具查询它们。
4. **文献计量指标无法计算**。中期报告 3.2.3 节为指标（9）–（12）、（16）给出了明确公式（完全/分数计数、高被引前 10% 分数分配、三年移动平均、CAGR、国际合作率、机构贡献份额与 HHI），WoS 元数据足以支撑计算，但项目没有任何计算工具。

## Solution

搭建一个包含论文与新闻两类知识源的低轨卫星星座竞争力分析智能体：

1. 将小论文的四类结构化成果（论文元数据与筛选、EASC 分类树、参数证据、参数族归一化）批量导入数据库，形成可 SQL 查询的结构化证据层；将论文全文按章节切分、嵌入后进入现有 pgvector RAG，与新闻语料并列形成非结构化证据层。
2. 新增四个 Agent 工具：论文检索、参数证据查询、技术层级（分类树）查询、文献计量计算，使智能体能够直接执行中期报告定义的指标计算。
3. 将现有单一 skill 拆分为论文要求的三个 SKILL.md，指标库对齐为 28 项，与结构化数据、检索工具的调用规则互相引用。
4. 为智能体运行建立可追溯记录（检索片段、来源、所选指标及理由、方法调用），支撑中期报告 3.4 节的客观检查。

数据流：

```
小论文CSV/PDF ──导入接口──> paper / taxonomy_node / paper_taxonomy / parameter_evidence 表
论文PDF全文  ──导入接口──> 章节切分 ──> bge-m3 嵌入 ──> chunk_bge_m3（论文KB，与新闻KB并列）
                                     │
Agent ── 三个Skill约束 ──> Tool调用（论文检索/参数证据/分类树/文献计量 + 现有hybridSearch/WebSearch）
                                     │
                              专题报告 + 运行追溯记录 ──> 客观检查评价
```

## Implementation Decisions

### 1. 数据模型（新增 4 张表）

- **paper**：论文元数据 + 筛选结论合一。字段含唯一业务标识 doc_id（WoS UT / CNKI 构造 ID）、来源库（WOS/CNKI）、标题、摘要、作者列表（JSON）、第一作者机构、第一作者国别、国别判定证据与置信度、发表年份、期刊、文献类型、被引次数、筛选状态（有效/排除）、排除原因。按 doc_id 唯一。
- **taxonomy_node**：EASC 分类树节点。业务标识 node_id（L1_xxx/V17BTC_xxx 等）、父节点、名称、层级、一级/二级领域、来源版本、状态、论文数。
- **paper_taxonomy**：论文—节点归属（doc_id、node_id、归属类型），支持一篇论文多节点。
- **parameter_evidence**：参数证据。保留源表关键字段：决策 ID、doc_id、技术对象、原始/规范参数名、参数族、原始值、比较符、最小/最大值、原始/规范单位、测试条件、证据原文、页码、章节、结果形式、人工审核状态、叶子节点 ID 与路径、第一作者国别、（联查得到的）发表年份。
- **chunk_bge_m3 沿用现表**：论文全文分块写入时在 metadata 中扩展 doc_id、章节名、页码，KB 维度区分论文库与新闻库。

### 2. 数据导入接口（REST，供研究者一次性/增量导入）

| 接口 | 用途 | 输入 |
|---|---|---|
| POST /api/papers/import/metadata | WoS/CNKI 元数据导入（upsert by doc_id） | 上传 CSV/TXT（WoS 制式或 CNKI 制式），参数指定来源库 |
| POST /api/papers/import/screening | 筛选结论导入（国别判定 + include 标记） | document_screen.csv |
| POST /api/papers/import/taxonomy | 分类树节点与层级导入 | nodes.csv + relationships.csv |
| POST /api/papers/import/taxonomy-memberships | 论文—节点归属导入 | paper_members.csv |
| POST /api/papers/import/parameters | 参数证据导入 | confirmed_parameters_final.csv（以人工审核后的最终字段为准） |
| POST /api/papers/import/corpus | 论文全文批量导入 RAG（切分+嵌入） | PDF 目录/清单；按 doc_id 关联 paper 表；复用现有批量上传并发管道与 SSE 进度推送 |
| GET /api/papers | 论文分页查询（过滤：年份、国别、技术节点、筛选状态、关键词） | — |
| GET /api/papers/{docId} | 论文详情（含技术归属、参数数量） | — |
| GET /api/papers/import/stats | 各表入库统计与最近导入批次结果 | — |

- 切分策略：论文全文优先按 Markdown 章节标题切分，超长章节二次切分；每块携带 doc_id、章节、页码元数据；新闻语料保持现状。
- 导入为后台任务 + SSE 进度（复用批量上传模式：CountDownLatch + 线程池 + finally countDown）。
- CSV 解析需处理 BOM、引号内逗号、多值字段（作者、机构）。

### 3. Agent 工具（实现现有 Tool 接口，OPTIONAL 类型）

| 工具 | 功能 | 支撑指标 |
|---|---|---|
| paperSearch | 论文元数据结构化过滤检索（年份/国别/机构/技术节点/文献类型/关键词），返回结构化论文列表 | (9)(11)(12)(16) |
| parameterEvidenceQuery | 参数证据查询（参数族/技术对象/国别/年份区间），返回参数记录 + 证据原文 + 页码 + 来源论文 | (13)(14) |
| taxonomyBrowse | 分类树查询（子树展开、节点论文数、中美论文分布、节点下论文列表） | 全部维度的技术层级组织 |
| bibliometricAnalysis | 文献计量计算：输入年份区间+过滤条件，输出完全/分数计数、高被引前 10%（含并列分数分配）、年度序列+三年移动平均+CAGR、国际合作率、机构份额+HHI+有效机构数 | (9)(10)(11)(12)(16) |

- 现有 KnowledgeTools（混合检索）与 WebSearchTool（外部检索）不动，由数据规则 Skill 约束其使用时机。
- bibliometricAnalysis 的计算逻辑独立为纯函数服务（输入论文记录集合、输出指标结果），工具层只做参数解析与格式化——公式与中期报告 3.2.3 节逐条对应，便于单测验证。
- 高被引参照组按"相同专题、相同发表年份、相同文献类型"构建；并列阈值按分数分配规则处理。

### 4. 三个 Skill（skills/ 目录，现有扫描机制加载）

- **competitiveness-framework（竞争力分析框架）**：28 项指标对齐中期报告表 2 及 3.2.1–3.2.4 各条目（战略重要性 5 项、技术前瞻性 3 项、科技创新能力 10 项、产业成熟度 10 项）；每项含定义、分析单元、数据字段、处理方式、解释边界；保留"按决策问题选最小足够指标组合"的选择规则与逐级指标选择建议；保留输出报告模式（问题界定→指标选择→证据与口径→分维度分析→综合判断）。
- **data-resource-rules（数据资源检索与使用规则）**：来源类型清单对齐中期报告表 1（政策规划/论文/专利/标准/项目产品任务/产业新闻/统计财务），对每类说明中美典型来源、证据角色、优先级与时效要求；明确本地新闻库、本地论文库（RAG）、结构化证据表（论文/参数/分类树）、外部 Web 检索四类资源的适用场景与调用顺序；规定引用格式（论文：作者-年份-标题-doc_id；参数：证据原文+页码；新闻：文档+分块标识；Web：URL+时间）。
- **ci-analysis-methods（竞争情报分析方法）**：五类方法的适用条件与操作要求（文献计量—对应 bibliometricAnalysis 工具；内容分析—编码维度与原文保留；比例比较—口径一致前提；时间路径分析—事件序列与阶段划分；定性研判—证据分级与推断标记）；跨来源参数比较的口径核对清单（任务、数据集、硬件、网络环境、基线、结果形式）；事实/计算/推断/缺口的区分与表达规范。
- 旧 space-tech-intelligence-analyst 删除（git 历史可回溯），避免新旧指标体系并存。
- Skill 元数据（frontmatter description）按"触发场景"写清分工，避免路由混淆。

### 5. 运行追溯与客观检查

- 新增运行记录模型：一次专题任务 = 问题说明 + Agent 配置 + 消息流（已有 chat_message）+ 工具调用记录（含参数与命中证据摘要）+ 最终报告。
- 客观检查接口：按运行 ID 输出检查清单（维度覆盖、指标选择理由、引用完整性、来源层级、检索与版本信息保留、方法调用可复核、结论对应证据、边界明确），每项可标记"符合/不符合/证据不足"并记录位置与修改意见。
- 证据引用导出：按运行 ID 汇总全部引用（分块、参数记录、论文元数据、Web 结果）供人工核验。

### 6. 关键既有能力（不改动，仅复用）

- 混合检索（向量 + BM25 + RRF 融合）与结构化检索结果（含命中标识）。
- 批量上传并发管道（CountDownLatch + 专用线程池 + SSE 进度）。
- Skill 扫描加载（SKILL.md → SkillDefinition → 注入 Agent）。
- 外部 Web 检索（时间范围 + 域名白名单）。
- Agent 的 ReAct 循环、SSE 推送、消息持久化。

## Testing Decisions

- **测试接缝选择**（由高到低）：
  1. **HTTP API 层**（导入与查询接口）：集成测试，走真实 Controller → Service → DB（PostgreSQL 测试库），用小论文目录中的小样本切片（如 20 条 WoS 记录、10 条参数记录、5 篇 PDF）作固定测试夹具。导入接口重点验证幂等（重复导入 upsert 不重复）与统计准确性。
  2. **Tool 接口层**（四个新工具）：单测 mock mapper 验证参数解析与结果格式化；集成测试用真实 DB 验证端到端查询。
  3. **文献计量纯函数层**：完全离线的单测——构造已知答案的小型论文集合（含国际合作论文、并列引用阈值、多机构论文），逐条断言公式输出与手算值一致。这是公式正确性的主要防线。
  4. **Skill 层**：沿用现有 Skill 扫描解析测试模式，验证三个 SKILL.md 可被扫描、frontmatter 合法、互相引用的指标编号一致。
- **好的测试标准**：只测外部行为（导入后的可查询结果、工具返回的结构、指标数值），不测内部实现细节（SQL 写法、切分函数的私有结构）。
