# 数据资源与证据使用规则

## 先冻结快照

每次聊天报告都创建新的 `snapshot_id`：先按当前问题重新发现和抓取网页，保存 URL、获取时间、原文文件及 SHA-256，然后只根据本轮已保存的证据分析和写报告。同一句话或等价问法再次提交，也创建独立运行和快照，不复用已有报告或应用层检索缓存。正式固定样本实验另记录时间范围、筛选条件、各表行数、数据库版本、代码提交号和 Skill 哈希；同组实验问法共享该固定样本，不改写旧快照。

正式语料与测试语料必须物理或逻辑隔离。测试文档不得进入正式知识库、正式统计表或正式快照；若发现污染，停止实验，清理后重新生成快照，受影响结果全部重跑。

## 本阶段允许的数据源

| 资源 | 访问方式 | 允许用途 | 禁止用途 |
|---|---|---|---|
| 论文结构化元数据 | PaperSearchTool | 指标 9、11、12、16 的过滤、分组与可追溯记录 | 不从 RAG 命中数反推论文数 |
| 文献计量计算 | BibliometricTool | 论文数、高被引、年度趋势、国际合作和机构集中度 | 不手工改写工具输出数值 |
| 参数证据表 | ParameterEvidenceTool | 指标 13、14 的参数族、对象、数值、单位、条件和页码 | 不承载发射次数和在轨卫星数量 |
| 冻结参数汇总 | ParameterSummaryTool | 论文分母、含参数论文数、参数记录数、年度和参数族分布、严格可比对数量 | 不用自由 SQL 混用全库与2020—2025窗口 |
| 技术分类 | TaxonomyBrowseTool | 限定低轨卫星星座网络技术范围 | 不把分类结果当作竞争力结论 |
| 论文全文 RAG | KnowledgeTool（论文 KB） | 方法、实验条件和参数语境 | 不以检索分块数代替论文数或参数记录数 |
| 原始机构事件快照 | 冻结事件表 | 指标 5、23、26 的正式事件统计 | 必须机器核验原网页、主体、日期、数值、单位并去重；不满足则排除 |
| 新闻报道样本 | KnowledgeTool（新闻 KB） | 事件线索和补充语境 | 不直接用于事件计数、发射/部署/在轨汇总或能力判断 |
| 本轮抓取的网页原文 | URL、获取时间、原文哈希和连续引文 | 逐项可定位的描述性事实；媒体信息注明为转述 | 不代替正式事件表，不由多篇网页直接求和或计算国别总量 |

## 实时网页证据分级（聊天报告管线）

聊天报告按当前问题实时采集网页时，来源分三层，层级跟随证据进入报告：

- L1 本地冻结与结构化数据：冻结事件表、论文表、参数表。新闻知识库（新闻 KB）命中只作线索——从线索中提取原始 URL 后必须重新抓取原文，线索文本本身不得直接充当证据或计数。
- L2 原始机构官网：SpaceX（spacex.com）、Amazon/kuiper（aboutamazon.com）、Blue Origin（blueorigin.com）、中国星网、垣信卫星、银河航天、国家航天局等主体自身发布页。标注“官方”。
- L3 权威第三方跟踪源：eoPortal、CelesTrak、Jonathan's Space Report、SpaceNews 正文、新华社等。标注“第三方汇编”。其余媒体一律按“媒体转述”处理。

规则：L3 来源的数字必须在报告中标注“第三方汇编”，媒体转述标注“转述，原始来源未核验”；中国主体检索必须包含中文检索词（如 千帆星座、国网星座、垣信）；分析阶段只使用已抓取原文，搜索摘要永远不是证据。

## 补检索回路

分析角色报告证据缺口（missingEvidence）时允许补检索，每任务最多 2 轮：第 2 轮检索词必须换来源层级或换语言（如官方页 → 第三方跟踪源、英文 → 中文），不得原样重复第 1 轮检索词。两轮后仍有缺口的字段在报告中列为证据缺口，不估算、不留空值参与计算。

网页发现和原始材料回查在本轮分析前完成；分析阶段只使用已抓取的原文，不把搜索摘要当成证据。旧实验快照保持不变。

## 调用与统计顺序

1. 聊天报告重新搜索并抓取本轮网页；固定样本实验读取正式快照清单。两者都验证 `snapshot_id`、来源和时间范围。
2. 数值先查结构化表，再调用公式工具；RAG 只补原文语境。
3. 论文计量按论文唯一标识去重；参数分析按参数证据记录统计，二者分母不得混用。
4. 新闻先形成结构化事件表，再按事件统计；同一事件的重复报道合并，保留全部来源文档标识。
5. 报告生成后核对引用是否属于当前快照，严禁引用测试文档和快照外材料。

新闻定量闸门按场景分派：固定样本实验必须先检查冻结事件表及原始机构来源，没有通过机器核验与日期、去重检查的事件时停止数值汇总；聊天报告没有冻结事件表，改走“本轮网页原文 + 逐字引文与数值核验”闸门——引文必须是原文连续片段、数值必须出现在引文或发布日期中，对比性计算数字只能来自计算层，不得在结论句中自行计算。两种闸门不混用；任何场景都不得改用报道、RAG 片段或模型记忆绕过闸门。

## 新闻事件记录最小字段

每条正式事件至少包含：`event_id`、`event_date`、`report_date`、`country`、`actor`、`action_type`、`object`、`quantity`、`unit`、`as_of_date`、`source_doc_id`、`source_excerpt`、`verification_status`、`snapshot_id`。

- 发射次数、部署批次和部署卫星数量按事件日期计入流量。
- 在轨卫星数量按 `as_of_date` 记录存量；没有基准日的数值不得进入国别对比表。
- 同一任务多篇报道不得用报道篇数代替事件数；报道数只能作为样本覆盖指标。
- 新闻中的数字若未回查原始发布主体，必须标注“新闻转述，原始来源未核验”。

## 冲突与缺失处理

- 结构化表与 RAG 文本冲突：回到源记录核对，不静默选择有利数值。
- 多篇新闻数量冲突：保留各版本、日期和来源，标注冲突；不能确认时不汇总。
- 事件发生日缺失：不得用报道日伪装事件日，可保留为空并说明。
- 未检索到公开信息：写“当前冻结样本未覆盖”，不得写成主体没有能力或事件没有发生。
- 新闻只是转述且未核验：保留 `verification_status=reported_unverified`，结论降级为样本线索。

## 引用格式

- 论文：`[docId] 标题（国别, 年份）`。
- 参数：`证据原文 + [docId] 第 N 页`，并给出参数、单位和条件。
- 论文全文：`[docId] 第 N 页`。
- 新闻：`[source_doc_id] 标题（来源, report_date）`；数量事实附原始机构 URL、`event_date/as_of_date` 和机器核验状态。
- 计算：`工具名(输入过滤条件, snapshot_id=...)`。

每个关键判断必须可回查到正式快照中的行、文档或计算输出。不得编造论文、参数、事件、日期、主体、机构、数值和排名。

每项事实、数值和证据性判断使用结构化引用 ID。外部来源指向具体原网页或 DOI，本地来源指向原始记录、片段和页码；聚合值保存输入 ID、公式和快照。报告正文只展示通过程序引用检查的内容。
